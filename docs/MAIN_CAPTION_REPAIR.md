本分支保留 GitHub main 現有視覺設計，修改字幕行為與必要的錯誤提示。不得用 LAB-008 的 HTML、CSS 或圖片覆蓋本分支。

## 三個實際版本

| 版本 | Commit | 實際流程 |
| --- | --- | --- |
| main／本分支基準 | `35c326c2046098a2bee99e9a909a726ea38e8fc7` | Node HTTP＋WebSocket；已傳送暫時與完整字幕，接收端翻成自己的語言。 |

| LAB-008 | `345eb539dd3a81dac344dc663bd4562c47ae4b72` | Worker／D1／HTTP 輪詢；只傳送完整辨識結果，發送端排隊翻譯，與 main 的協定不同。 |

LAB-008 的 final-only 傳送、輪詢視窗與發送端 Key 依賴，不能直接當成 main 上卡安裝置問題的確診。這次以 main 程式為基礎整合 PR #18；只移植可驗證的期限、佇列與辨識生命週期處理，不複製 LAB 的介面或 Worker API。

## 不可變動的介面基準

`public/index.html`、`public/style.css`、所有圖片與靜態資源保持和上述 main 一致。首頁、封面、雙愛心、聊天室、較大的雙語字幕、按鈕位置及原有配色均保留。錯誤狀態使用現有的 `speechStatus`、`speechPeerStatus`、`speechRetry` 與字幕泡泡，不新增設計系統。

## 修復範圍

- 原文立即顯示，完整句優先，暫時字幕翻譯只占一個工作槽。
- 等待佇列同時限制數量與時間；取消／逾時不依賴供應商真的停止回應，避免工作槽卡住。
- 完整句及更新的字幕取代過期工作，保留原文與明確重試狀態；舊結果不能覆蓋新句。
- WebRTC 的連線狀態及 ICE connected／completed 均可觸發辨識啟動，避免只等單一瀏覽器事件。
- 正常語音辨識結束使用新實例接續；網路錯誤、啟動逾時、反覆失敗與背景切換有錯誤提示及手動重啟。
- 雙方狀態分開，傳送固定列舉的狀態／原因，不把任意錯誤內容、token 或裝置網路資訊傳給對方。
- 保留 WebRTC 原聲；字幕失敗不得停止媒體，也不加入 AI 翻譯朗讀。

## 不在這次正式啟用的功能

PR #17 的永久聊天紀錄、Email OTP、Supabase RLS／授權仍是獨立開發版，目前有合併衝突及正式環境設定尚待處理。不得整份覆蓋本分支，不能把未部署與未驗收的資料持久化、帳號或備份宣稱為完成。先完成本次字幕分支審查，再處理 PR #17 的重新整合與資料遷移。

## 真實裝置仍需驗收

自動測試使用模擬語音辨識／媒體與翻譯供應商；即使用實際本地 HTTP／WebSocket，也不是雙人電話實測。

1. 兩支手機進同一房間，A 選繁中、B 選英文。B 說英文時，A 必須看到英文原文與繁中；反向也要成立。
2. 交替說至少 20 句並持續通話，檢查等待時間是否隨字幕增加而拉長。
3. 兩支 iPhone Safari 分別驗證麥克風／辨識權限、Siri／聽寫、需要手動啟動的情況，以及 Web Speech 與 WebRTC 同時使用麥克風的實際相容性。
4. 拒絕權限、切換背景、靜音／恢復及切換網路，確認原因清楚、可重啟、原聲不中斷。
5. 語音與視訊都要驗證；相機切換、拍照、特效、訊息翻譯、搜尋與台灣／瑞典時鐘不得退化。
6. 掛斷後相機／麥克風釋放，重撥不接收前次字幕。

## 發布限制

此分支透過新的 PR 審查，不直接推送或合併 main，不觸發 Render 正式部署。合併與正式部署前須取得使用者對具體版本的確認。LAB-008 仍是另一套程式，不能把它的測試網址宣稱為本分支已部署的預覽。
